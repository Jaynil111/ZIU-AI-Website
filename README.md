# ZIU AI — Website

The marketing website for **ZIU AI**: AI consulting, custom automation and software for growing businesses.
Its signature is a vertical, layered **glass wall**, ray-traced in real time in the browser,
with a short cinematic intro and a resolution-independent, extruded vector logo on the homepage.

- **Static site:** plain HTML, CSS and JavaScript generated by a small Node script. No framework, no runtime dependencies.
- **26 pages:** home, services, solutions (overview + 6 detail pages), industries, regions (4), pricing, how we work, product portfolio (plus the legacy case-studies URL), resources, about, careers, contact, automation check, privacy, terms and 404.
- **Content:** site copy v2.0 (8 November 2026), American English. The offer is told as three pillars: **Advise. Build. Run.** All published pages contain finished copy; the checks reject unfinished placeholders.

---

## Quick start

Requires **Node.js 18 or later** (Python 3 only for `npm run serve`).

```bash
npm install        # installs the two self-hosted font packages
npm run build      # renders every page into dist/
npm run dev        # serves dist/ at http://localhost:4174
```

The dev server doesn't rebuild on its own: run `npm run build` again after any change in `src/`.

| Script | What it does |
| --- | --- |
| `npm run build` | Renders all pages and copies assets into `dist/` (assets get a content hash for cache busting) |
| `npm run dev` | Local server on port 4174 that also accepts test form posts (`/api/forms-dev`) |
| `npm run serve` | Plain static server on port 4173 (Python) |
| `npm run check` | Build, then `tools/reconcile.mjs` and `tools/check.mjs`; fails on gaps, placeholders, empty content headings, missing assets or broken links |

## Editing content

| To change | Edit |
| --- | --- |
| Email, address, founder name | `OWNER` in `src/data.mjs` |
| Engagement descriptions, durations and scope | `ENGAGEMENTS` in `src/data.mjs`; pricing is always based on customer requirements |
| Pillars, services, use cases, FAQs, industries, regions, application guide, who it is for | the lists in `src/data.mjs` |
| Homepage sections | `src/home.mjs` |
| Any other page, page titles and SEO descriptions | `src/pages.mjs` |
| Header, footer, navigation, button labels | `NAV`, `CTA` and `footer` in `src/components.mjs` |
| Colors, type, spacing | the variables at the top of `src/assets/styles.css` |
| Intro length | `INTRO_SECONDS` in `src/assets/intro.js` (about 2.5 s now) |
| Large 3D logo | vector outlines, extrusion and materials in `src/logo3d.mjs`; reveal styling in `src/assets/styles.css` |

Then run `npm run check`. If you change approved copy on purpose, update the matching
string in `tools/reconcile.mjs` too, or the check will report it as missing. The same
check fails on any British spelling, so the site stays in American English.

### Content verification

Run `npm run check` before publishing. The checker rejects bracketed editorial placeholders, empty headings, missing assets and broken internal links. Add products in `src/products.mjs` with a name, public URL and description. Keep the privacy notice aligned with the form provider and browser storage used by the site.

The Web3Forms key determines the delivery mailbox. Changing `OWNER.email` updates public contact links; it does not change the mailbox registered with Web3Forms.

## Forms

The contact form and the automation check send through **Web3Forms**, set in
`src/site.config.mjs`. Each submission includes every field plus `subject`, `form`
(contact / automation-check) and `page`. A hidden spam-trap field drops bot submissions.
If sending fails, the visitor keeps their answers, sees an error with the contact email,
and can retry. Without JavaScript the forms post natively.

Other providers are supported:

| Provider | Settings in `src/site.config.mjs` |
| --- | --- |
| Web3Forms (current) | `provider: 'web3forms'`, `accessKey: '<key>'` |
| Formspree | `provider: 'formspree'`, `endpoint: 'https://formspree.io/f/<id>'` |
| Netlify Forms | `provider: 'netlify'` (only when hosted on Netlify) |
| Custom | `provider: 'custom'`, `endpoint: '<url>'` (any JSON POST endpoint) |

Each setting can also come from an environment variable at build time:
`FORM_PROVIDER`, `FORM_ENDPOINT`, `FORM_ACCESS_KEY`.

The Web3Forms access key is a public, client-side key by design, so it is safe in the repo.

**Test locally without sending real email:**

```bash
FORM_PROVIDER=custom FORM_ENDPOINT=/api/forms-dev npm run build
npm run dev        # submissions are saved to .form-submissions.jsonl
```

`/api/forms-dev?fail=1` returns an error so you can see the failure state.
Run `npm run build` again afterwards to go back to Web3Forms.

## Features

**Glass**
- Homepage intro and hero: a live ray-traced glass wall (`glass.js`) with refraction, polished bevels and caustics, adaptive resolution and 2x anti-aliasing.
- Page headers, call-to-action bands and the founder portrait: sharp stills of the same glass (`glass-still.js`), drawn once each in small pieces so scrolling never stutters. CSS glass is the fallback.

**Logo**
- One vector source (`src/logo3d.mjs`) provides every ZIU AI wordmark: header, mobile navigation, footer, loader, intro and closing section.
- Clear glass faces and ruby-tinted lower sections retain the brand colors, with translucent depth, beveled edges and diagonal reflections.
- Large logos gently turn, while a light sweep animates across all visible wordmarks. Offscreen animations pause, and reduced motion shows a complete static logo.
- The favicon uses the same glass Z geometry, with a dark backing and no animation for small-size legibility. Its URL is versioned when the artwork changes.
- The original video remains in `src/media/` as a reference and is no longer displayed.

**Intro**
- Branded loader, then a short fly-through the glass wall (about 2.5 seconds), then the 3D vector wordmark reveal.
- **Skip** at any time; clicking the logo replays it. Going back to the homepage skips it and restores your scroll position.

**Motion**
- Fade transitions between pages (View Transitions API, where supported).
- Reading-progress line, word-by-word headings, line icons that draw on, timelines that fill as you scroll, glass panes moving at different depths.
- Smooth wheel scrolling on desktop; touch, keyboard and scrollbar stay native.
- Glass cursor on desktop.

**Glass piano (homepage hero)**
- Each glass pane of the hero wall is a piano key: click or tap one to play a note (tuned left to right to C major pentatonic). The pane rings with light: a ruby glow and a band of light traveling up the glass.
- The sound is a real recorded grand piano: nine notes (C4–C6) of the [Salamander Grand Piano](https://github.com/sfzinstruments/SalamanderGrandPiano) by Alexander Holm, CC BY 3.0, in `src/assets/piano/` (about 530 KB, fetched when the pointer first rests on a pane). Notes in between replay the nearest recording at the right pitch. The attribution is in the Audio credits section of the Terms page and must stay while the samples are used.
- If the recordings cannot load, `piano.js` falls back to a synthesized piano. Nowhere else on the site makes sound.

**Tools**
- Savings calculator on Resources (`/resources/#savings`); uses only the visitor's own figures, shows the formula, and can prefill the contact form.
- Interactive automation walkthrough on the homepage.

**Accessibility**
- Everything is disabled under reduced motion, with complete static states.
- One `h1` per page, ordered headings, labelled form fields, keyboard navigation, minimum 40px tap targets; checked by `npm run check`.

## QA switches

Add these to the URL:

| Switch | Effect |
| --- | --- |
| `?p=0.5` | Freeze the intro at a point (0–1); `?p=1` goes straight to the hero |
| `?key=3` | Hold the piano light on hero pane 3 (to check the glow) |
| `?gl=0` | Force the no-WebGL fallback |
| `?motion=reduce` | Simulate the reduced-motion setting |
| `?smooth=0` | Turn off smooth wheel scrolling |
| `?cursor=0` | Turn off the glass cursor |

## Deploying

`dist/` is generated, so the host builds it:

| Host | Setup |
| --- | --- |
| **Netlify** | Import the repo; `netlify.toml` sets build command `npm run build` and publish directory `dist` |
| **Vercel** | Import the repo; `vercel.json` sets the same |
| **Cloudflare Pages** | Build command `npm run build`, output directory `dist` |

Links are root-relative (`/services/`), so serve the site from the root of a domain.
A GitHub Pages *project* site, which lives under `/<repo-name>/`, would need a base path added first.

## Product portfolio

Edit `src/products.mjs` to add or update products. Each entry contains `name`, `url` (a public HTTP/HTTPS link), and `description`. Rebuild with `npm run check`. The same entries appear on the homepage and `/portfolio/`. The former `/case-studies/` URL also displays the portfolio for existing bookmarks.

## Single-step inquiries

`/contact/#book` is the call-request form: name, work email, optional company, and a brief description. Visitors request a call; a time is arranged by email. `/automation-check/` is also a single-step form with name, work email, a task description, and optional applications. Both use the existing provider configuration and retain validation, spam protection, and submission feedback.
